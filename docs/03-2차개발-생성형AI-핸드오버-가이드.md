# 2차 개발을 위한 생성형 AI 핸드오버 가이드 (AI Prompt Kit)

> **학생 안내**: 이 문서는 1차 완성된 스마트 기상 시스템을 바탕으로, **생성형 AI(ChatGPT, Claude, Gemini, Antigravity 등)에게 프로젝트의 전체 맥락을 전달하고 2차 완성(라즈베리파이 5 실기기 연동, 기능 추가, 클라우드 배포)을 요청할 때 사용하는 가이드**입니다.
> 
> 새로운 AI 채팅창을 열 때 아래 **[1. 생성형 AI 입력용 기본 시스템 프롬프트]**를 복사해서 먼저 입력한 뒤, 원하는 기능 추가를 질문하세요.

## 1. 생성형 AI 입력용 기본 시스템 프롬프트 (복사해서 AI에게 제공)

```markdown
당신은 "스마트 기상 시스템(Smart Wake-up System)" 프로젝트의 전문 페어 프로그래밍 AI 어시스턴트입니다.
현재 우리 팀은 Windows PC 환경에서 Mock-up(가상 하드웨어) 기반의 1차 완성형 시스템을 구축 완료했으며,
이제 2차 완성(라즈베리파이 5 실기기 연동, 센서/액추에이터 추가, 영상인식 고도화, 배포)을 진행하려고 합니다.

기존에 완성된 아키텍처와 API 계약, 파일 구조를 엄격히 준수하여 코드를 제안해야 합니다.

### [프로젝트 개요 및 핵심 데이터 흐름]
- 팀 주제: 알람 이후 기상 미션과 2차 수면 방지 기능을 포함한 스마트 기상 시스템
- 핵심 시나리오:
  1. 설정된 시각 또는 타이머에 도달하면 알람(피에조 부저)이 울리기 시작함.
  2. 사용자가 웹캠(YOLOv8) 앞에서 지정 미션(사람 감지 또는 물병/책 등 사물 인식)을 수행하면 알람이 자동 해제됨.
  3. 미션 성공 약 25초 후 대시보드 및 하드웨어 화면에 "2차 수면 방지 기상 확인 팝업"이 발생함.
  4. 15초 내에 터치패드를 누르거나 확인 버튼을 누르지 않으면 "2차 수면 감지"로 판단하여 알람이 다시 울림.

### [기술 스택]
- 백엔드: FastAPI (Python 3.12+), Uvicorn, WebSockets
- 데이터베이스: MySQL / MariaDB (로컬) → Supabase PostgreSQL (배포 시)
- 프론트엔드: Next.js 16 (React 19, TypeScript, Tailwind CSS, Lucide Icons)
- 영상인식: Python 3.12, YOLOv8 (ultralytics), MediaPipe, OpenCV, ONNX Runtime (ArcFace/YuNet+SFace), Pillow (한글 출력)
  *※ 주의: Windows C++ 컴파일 에러를 유발하는 dlib / face_recognition은 절대 설치/사용하지 않고, onnxruntime / OpenCV DNN / mediapipe를 사용한다.*
- 하드웨어: 1차는 Windows GUI Mock 데몬(Tkinter + winsound), 2차는 라즈베리파이 5(gpiozero, lgpio)

### [디렉터리 및 핵심 파일 구조]
- backend/
  ├── main.py                  # FastAPI 앱 엔트리포인트, CORS, WebSocket 마운트
  ├── auth.py                  # API Key (디바이스용) 및 User Role 인증 미들웨어
  ├── websocket_manager.py     # 실시간 WebSocket 브로드캐스트 매니저
  ├── db/
  │   ├── init.sql             # 테이블 생성 및 디바이스 시드 데이터 DDL
  │   └── database.py          # PyMySQL 연결 풀 및 CRUD 헬퍼 함수
  ├── routers/
  │   ├── devices.py           # 디바이스 제어(/api/devices) 및 desired-state 폴링(/api/v1/devices)
  │   ├── alarm.py             # 알람 예약(/api/alarm/schedule), 즉시 울림(/trigger), 정지(/stop)
  │   └── vision.py            # 비전 감지 이벤트 수신(/api/v1/vision/events), 기상 확인
  └── services/
      └── trigger_service.py   # 기상 미션 판정 및 2차 수면 방지 타이머 엔진
- frontend/
  ├── app/page.tsx             # 실시간 대시보드 메인 페이지 (WebSocket 수신 및 상태 관리)
  └── components/dashboard/
      ├── ActuatorCard.tsx     # 피에조 부저 상태 표시 및 On/Off 제어 카드
      ├── SensorCard.tsx       # 터치패드/카메라 측정치 표시 카드 (읽기 전용)
      ├── AlarmScheduleCard.tsx# 알람 시각 설정(HH:MM) 및 5초/10초 테스트 타이머 카드
      ├── AlertCard.tsx        # 알람 경보 발생 시 깜빡이는 경고 카드
      └── VisionLogList.tsx    # 실시간 비전 감지 로그 리스트
- vision/
  ├── main.py                  # 웹캠 영상 캡처, YOLOv8 추론, 백엔드 이벤트 HTTP POST 전송
  └── yolov8n.pt               # YOLOv8 경량 객체 탐지 가중치 모델
- pi/
  └── main.py                  # 하드웨어 클라이언트 (1초 주기 백엔드 desired-state 폴링 및 비프음 재생)

### [핵심 통신 및 API 계약]
1. 인증 헤더:
   - 디바이스(Vision / Pi) 통신: Header `X-Device-API-Key: {DEVICE_API_KEY}`
   - 사용자/대시보드 통신: Header `X-User-Role: admin`
2. 하드웨어 폴링 계약 (1초 주기):
   - 폴링 (하드웨어가 백엔드에 목표 상태 확인): `GET /api/v1/devices/{device_id}/desired-state`
   - 상태 보고 (하드웨어가 실제 상태를 백엔드에 보고): `POST /api/v1/devices/{device_id}/state`
     Body: `{"current_state": "ringing"|"off", "current_value": {...}}`
3. 알람 제어 API:
   - 시각 예약/타이머: `POST /api/alarm/schedule` (Body: `{"alarm_time": "07:30"}` 또는 `{"in_seconds": 5}`)
   - 즉시 발동: `POST /api/alarm/trigger`
   - 알람 정지: `POST /api/alarm/stop`
   - 기상 확인(2차 수면 방지 팝업 응답): `POST /api/alarm/confirm-wakeup` (Body: `{"actor": "user"|"touch_pad"}`)
4. 비전 감지 이벤트 API:
   - `POST /api/v1/vision/events`
     Body: `{"event_type": "person_detected"|"bottle_detected", "detected": true, "count": 1, "confidence": 0.85}`
5. 실시간 WebSocket 이벤트 (`ws://localhost:8000/ws`):
   - `device_state`: 디바이스 상태 변경 브로드캐스트
   - `alarm_triggered`: 알람 개시
   - `mission_success`: 기상 미션 성공
   - `wakeup_check_popup`: 2차 수면 방지 팝업 띄우기 (타임아웃 카운트다운 포함)
   - `re_alarm`: 2차 수면 감지로 인한 재알람 발생
   - `wakeup_confirmed`: 최종 기상 확인 완료

### [DB 테이블 및 디바이스 ID 목록]
- 디바이스 ID:
  - `buzzer_1` (kind: 'buzzer') : 알람 출력 장치(피에조 부저)
  - `touch_pad_1` (kind: 'touch_pad') : 패드 화면/터치 입력
  - `camera_1` (kind: 'camera') : 기상 감지 카메라
- 테이블: `devices`, `sensor_readings`, `control_log`, `vision_events`
```

## 2. 왜 폴더 구조와 API 연동 규약이 AI에게 필요한가요?

| 항목 | 누락되었을 때 발생하는 문제 | 자료를 제공했을 때의 효과 |
|---|---|---|
| **폴더 및 파일 구조** | AI가 엉뚱한 위치에 새 파일을 만들거나, 기존 모듈과 중복되는 코드를 작성하여 Import 에러가 발생함 | 정확히 수정해야 할 파일의 특정 함수만 짚어서 외과적으로 수정해 줌 |
| **API 경로 및 Request Body** | AI가 임의로 만든 URL(예: `/alarm/start`)로 요청하여 404/422 에러 발생 | 백엔드와 프론트엔드, 하드웨어 간에 데이터가 한 번에 통신됨 |
| **인증 헤더 규약** | `X-Device-API-Key`나 `X-User-Role` 헤더를 누락하여 401 Unauthorized 에러 발생 | 디바이스와 대시보드 권한에 맞는 헤더를 자동으로 포함하여 작성함 |
| **하드웨어 폴링 계약** | 하드웨어가 백엔드의 desired-state를 읽지 못해 웹에서는 알람이 울려도 라즈베리파이 부저가 울리지 않음 | `desired_state` 확인 후 일치시키는 올바른 하드웨어 데몬 코드를 작성함 |

### 과제 A. 라즈베리파이 5 실기기 연동 (`pi/main.py` 실제 GPIO 전환)

> **질문 템플릿**:
> ```text
> 우리 팀 시스템 프롬프트를 확인했지?
> 현재 pi/main.py는 Windows PC용 Tkinter GUI와 winsound 비프음으로 동작하는 Mock 프로그램이야.
> 이것을 실제 "라즈베리파이 5"에서 동작하는 데몬 코드로 전환하려고 해.
>
> - 라즈베리파이 5의 GPIO 18번 핀에 피에조 부저를 연결했고, GPIO 24번 핀에 터치 버튼(센서)을 연결했어.
> - gpiozero 라이브러리(Buzzer, Button)를 사용할 거야.
> - 백엔드의 GET /api/v1/devices/buzzer_1/desired-state 를 1초마다 폴링해서 'ringing'이면 부저를 울리고, 'off'면 멈추게 해줘.
> - 버튼이 눌리면 백엔드의 POST /api/alarm/confirm-wakeup 으로 기상 확인을 전송하게 해줘.
> - 백엔드와 통신할 때 X-Device-API-Key 헤더를 적용해줘.
>
> 라즈베리파이 5에서 바로 실행 가능한 pi/main.py 코드를 작성해줘.
> ```

### 과제 C. 영상인식 미션 다양화 및 얼굴/제스처 고도화

> 💡 **비전 AI 개발자 필수 지침**:
> - **`dlib`, `face_recognition` 설치 절대 금지**: Windows에서 C++ 컴파일러(Visual Studio Build Tools) 미설치로 심각한 설치 오류가 발생합니다.
> - **얼굴 감지/인식 시**: LFW 99.5%+ 인식률의 `onnxruntime`(경량 ArcFace ONNX), OpenCV DNN(`YuNet` + `SFace`), 또는 `mediapipe`를 사용합니다.
> - **한글 텍스트 출력 시**: OpenCV `cv2.putText` 대신 `Pillow`(PIL `ImageDraw`, `ImageFont`)를 사용하여 글자 깨짐(`???`)을 방지합니다.

> **질문 템플릿 (손동작 / 가위바위보 미션)**:
> ```text
> 현재 vision/main.py는 YOLOv8을 사용해서 사물(물병, 책 등)을 인식하고 있어.
> 여기에 MediaPipe Hands를 추가해서 "가위바위보" 중 특정 손동작(예: 보자기🖐️)을 카메라에 3초 동안 보여주어야 알람이 꺼지는 미션으로 고도화하고 싶어.
> (한글 안내 문구는 Pillow를 이용해 웹캠 화면에 깔끔하게 오버레이해줘.)
>
> - vision/main.py에서 손동작을 판정하는 로직
> - 판정 성공 시 백엔드의 POST /api/v1/vision/events 로 {"event_type": "gesture_paper", "detected": true} 를 전송하는 방법
> - 백엔드 trigger_service.py에서 이 이벤트를 받아 미션 성공으로 처리하는 방법
> 
> 단계별 코드 수정안을 알려줘.
> ```

> **질문 템플릿 (얼굴 인식 및 2차 수면/눈 깜빡임 감지 고도화)**:
> ```text
> 우리 스마트 기상 시스템의 2차 수면 방지 기능을 위해 웹캠으로 사용자의 얼굴과 눈 깜빡임(또는 ArcFace ONNX 기반 사용자 본인 얼굴 인증)을 판정하고 싶어.
> - Windows 환경이므로 C++ 빌드 에러가 나는 dlib 대신 onnxruntime(경량 ArcFace ONNX) 또는 OpenCV DNN(YuNet+SFace) / MediaPipe Face Mesh를 사용해줘.
> - 웹캠 화면의 "기상 확인 중...", "눈을 뜬 상태 유지" 등의 한글 문구는 Pillow를 사용해 렌더링해줘.
> - 얼굴 인식 및 수면/기상 상태 판정 결과를 백엔드 /api/v1/vision/events 로 전송하는 코드를 작성해줘.

### 과제 D. Supabase 및 Render / Vercel 클라우드 배포

> **질문 템플릿**:
> ```text

## 4. 생성형 AI와 협업할 때 지켜야 할 원칙

1. **한 번에 한 파일/한 기능씩 요청하기**:
   - "전부 다 고쳐줘"라고 하면 AI가 기존 정상 동작 코드를 임의로 생략하거나 누락할 수 있습니다.
   - "먼저 라즈베리파이 부저 제어 부분만 작성해줘", "그다음 버튼 입력 전송 부분을 추가해줘"와 같이 단계별로 진행하세요.
2. **에러가 발생하면 에러 로그 전문을 그대로 전달하기**:
   - "안 돼요" 대신 터미널에 출력된 빨간색 에러 메시지(Traceback)를 복사해서 질문하세요.
3. **직접 눈으로 확인하고 테스트하기**:
   - AI가 코드를 작성해주면 반드시 저장 후 터미널에서 실행해보고 동작을 확인하세요.
