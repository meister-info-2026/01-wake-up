## 0단계. 저장소 클론 및 워크스페이스 준비 (팀당 1회)

### 0-1. GitHub 저장소의 `wakeup` 브랜치 클론
PowerShell에서 아래 명령어를 실행하여 1차가 완성된 `wakeup` 브랜치를 클론합니다:
```powershell
git clone -b wakeup https://github.com/foxjini/agent-vibe-coding-starter-kit2.git iot-vision-control-system
cd iot-vision-control-system
```

**확인**: 폴더 내에 `AGENTS.md`, `backend/`, `frontend/`, `vision/`, `pi/`, `run_system.ps1` 등이 존재하면 성공입니다.

### 0-2. Antigravity IDE로 열기
Antigravity IDE를 실행하고 `iot-vision-control-system` 폴더를 워크스페이스로 엽니다.

### 0-3. Antigravity Rules 설정 확인
상단 "…" 메뉴 → **Customizations** 패널(또는 Rules 탭)에서 아래 **3개 규칙만 "Always On"**으로 설정되어 있는지 확인합니다:
- `karpathy-principles` (생각 먼저·단순함 우선·외과적 변경)
- `security-rules` (시크릿 보호)
- `coding-standards` (코드 품질 표준)

> ⚠️ 나머지 규칙(`hardware-rules`, `vision-rules`, `api-rules`, `db-rules` 등)은 Always On으로 켜지 마세요. 필요할 때 각 Agent가 자동으로 읽어오므로 토큰을 크게 아낄 수 있습니다.

## 1단계. 환경변수(.env) 설정 및 패키지 원클릭 설치

### 1-1. 환경변수 파일 복사 (`.env`)
각 하위 폴더의 `.env.example` 4개를 복사해 `.env`를 만듭니다:
```powershell
copy backend\.env.example backend\.env
copy frontend\.env.example frontend\.env
copy vision\.env.example vision\.env
copy pi\.env.example pi\.env
```
> 💡 **보안 및 통신 확인**: `backend/.env`, `vision/.env`, `pi/.env` 파일 안의 `DEVICE_API_KEY`는 서로 일치해야 합니다 (기본값: `dev_secret_key_1234`).

### 1-2. 패키지 의존성 설치

#### ① backend/ — Python venv 및 패키지 설치
```powershell
cd backend
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
cd ..
```

#### ② frontend/ — Next.js 의존성 설치
```powershell
cd frontend
npm install
cd ..
```

#### ③ vision/ — 초경량 ONNX 비전 가상환경 설치
> 🚀 **초경량 ONNX 탑재**: 수 GB의 PyTorch 없이 12.8MB 경량 `yolov8n.onnx` 모델과 `onnxruntime`으로 5~10초 만에 가볍게 설치됩니다.
```powershell
cd vision
py -3.12 -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
cd ..
```

## 2단계. 로컬 DB 설정 및 1차 시스템 베이스라인 동작 검증

1차로 완성된 기능(알람 예약 → 비프음 알람 → 웹캠 인물 감지 미션 해제 → 25초 후 2차 수면 방지 팝업)을 직접 실행해서 눈으로 확인합니다.

### 2-1. MariaDB 데이터베이스 초기화
1. **XAMPP Control Panel**에서 **MySQL(MariaDB)을 'Start'** 합니다.
2. PowerShell에서 `init.sql`을 실행해 DB(`smart_alarm`)와 테이블, 시드 데이터를 생성합니다:
```powershell
cd backend
Get-Content db\init.sql | mysql -u root
cd ..
```
*(mysql 명령이 환경변수에 없다면 phpMyAdmin 웹 화면 `http://localhost/phpmyadmin`의 **SQL 탭**에 `backend/db/init.sql` 내용을 붙여넣고 실행해도 됩니다.)*

### 2-2. 1차 시스템 통합 실행
시스템 실행 방법은 **[방법 A: 자동 스크립트]**와 **[방법 B: 개별 멀티 터미널]** 중 선택할 수 있습니다.

#### [방법 A: 간편 실행] PowerShell 스크립트 이용
프로젝트 루트에서 제공되는 통합 구동 스크립트를 실행합니다:
```powershell
.\run_system.ps1
```
*(백엔드, 프론트엔드, 비전, 가상 하드웨어 Mock GUI 창이 각각 새 창으로 자동 실행됩니다.)*

#### [방법 B: 멀티 터미널 개별 실행] (디버깅 시 권장)
4개의 터미널을 열어 각각 실행합니다:
- **터미널 1 (백엔드 API/WS)**:
  ```powershell
  cd backend; .\venv\Scripts\Activate.ps1; uvicorn main:app --reload --host 0.0.0.0 --port 8000
  ```
  *(※ `--host 0.0.0.0`을 지정해야 동일 Wi-Fi 망의 라즈베리파이 5나 모바일 기기 등 외부 시스템에서 접근할 수 있습니다.)*

- **터미널 2 (대시보드 웹)**:
  ```powershell
  cd frontend; npm run dev
  ```
- **터미널 3 (웹캠 비전 클라이언트)**:
  ```powershell
  cd vision; .\venv\Scripts\Activate.ps1; python main.py
  ```
- **터미널 4 (하드웨어 Mock 데몬)**:
  ```powershell
  cd pi; python main.py
  ```

### 2-3. 1차 동작 시나리오 검증 체크
1. **대시보드 접속**: 브라우저에서 `http://localhost:3000` 접속 → 상단 배지가 **"● 실시간 연결됨"**으로 초록색 점등되는지 확인.
2. **알람 테스트 예약**: 대시보드의 **"5초 후 테스트"** 버튼 클릭.
3. **알람 울림 확인**: 5초 뒤 피에조 부저 Mock(PC 사운드 비프음)이 울리며 대시보드에 경보 화면 발생.
4. **기상 미션 수행**: 웹캠 창 앞에 사람이 서면, YOLO가 사람을 인식(`person_detected`)하여 백엔드로 이벤트를 전송하고 **알람이 즉시 해제**됨.
5. **2차 수면 방지 팝업 확인**: 알람 종료 약 25초 후, 대시보드와 Mock GUI 화면에 **"2차 수면 방지 기상 확인" 팝업**이 발생.
6. **기상 확인 완료**: 팝업의 "기상 확인" 버튼을 클릭하여 최종 기상 완료 상태로 전환되는지 확인.

## 3단계. 2차 개발 ① — 라즈베리파이 5 실기기 연동 (Mock → Hardware)

PC의 가상 사운드/GUI Mock을 **실제 라즈베리파이 5와 피에조 부저/터치 센서**로 교체하는 단계입니다.
상세한 통신 규약은 **[`docs/부록A-백엔드-라즈베리파이5-연동-인터페이스-가이드.md`](부록A-백엔드-라즈베리파이5-연동-인터페이스-가이드.md)** 및 **[`docs/부록C-라즈베리파이5-담당자-온보딩-슬라이드.pptx`](부록C-라즈베리파이5-담당자-온보딩-슬라이드.pptx)**를 참고합니다.

### 3-1. 라즈베리파이 5 환경 설정 (라즈베리파이 터미널)
라즈베리파이 5는 RP1 칩 제어를 위해 `lgpio` 라이브러리가 필수입니다:
```bash
cd pi
python3 -m venv venv
source venv/bin/activate
pip install gpiozero lgpio requests python-dotenv
```

### 3-2. 백엔드 IP 연동 및 환경변수 수정
1. **Windows PC 백엔드 실행 옵션 확인**:
   라즈베리파이와 같은 외부 기기에서 백엔드에 접근하려면 uvicorn이 모든 네트워크 인터페이스에 바인딩되어야 합니다.
   ```powershell
   # backend 폴더에서 반드시 --host 0.0.0.0 옵션 포함하여 실행
   uvicorn main:app --reload --host 0.0.0.0 --port 8000
   ```
   > ⚠️ **Windows 방화벽 주의**: Windows 보안 경고 창이 뜨면 **"개인 네트워크" 액세스를 허용**해야 합니다. 연결이 계속 거부되면 PowerShell(관리자)에서 8000번 포트 허용 규칙을 추가하세요:
   > `New-NetFirewallRule -DisplayName "FastAPI 8000" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow`

2. Windows PC의 IP 주소를 확인합니다:
   ```powershell
   ipconfig
   # 예: 무선 LAN / 이더넷 어댑터의 IPv4 주소가 192.168.0.25 라면
   ```
3. 라즈베리파이의 `pi/.env` 파일을 수정합니다:
   ```env
   # 주의: localhost 대신 위에서 확인한 Windows PC의 사설 IP를 입력합니다.
   BACKEND_URL=http://192.168.0.25:8000
   DEVICE_API_KEY=dev_secret_key_1234
   DEVICE_MODE=hardware
   ```
4. Windows PC 백엔드의 `backend/.env`를 실기기 모드로 변경합니다:
   ```env
   DEVICE_MODE=hardware
   ```

### 3-3. 하드웨어 배선 및 데몬 구동
1. **전원을 끈 상태**에서 피에조 부저(GPIO 18 권장) 및 버튼/터치센서(GPIO 24 권장)를 연결합니다.
2. 교사 입회 하에 전원을 켜고 라즈베리파이에서 데몬을 실행합니다:
   ```bash
   python main.py
   ```
3. **확인**: 대시보드에서 알람 발생 시 실제 피에조 부저에서 소리가 나고, 터치 시 백엔드로 상태가 보고되는지 확인합니다.

## 4단계. 2차 개발 ② — 스마트 기상 시스템 기능 고도화

1차 구축된 시스템에 다양한 기상 미션과 2차 수면 방지 강화 기능을 추가합니다.
이 과정은 **[`docs/03-2차개발-생성형AI-핸드오버-가이드.md`](03-2차개발-생성형AI-핸드오버-가이드.md)**의 프롬프트 키트를 복사하여 AI 어시스턴트(ChatGPT, Claude, Gemini, Antigravity)와 함께 진행합니다.

### 4-1. 권장 고도화 기능 아이디어
1. **기상 미션 다양화 (비전 인식 고도화)**:
   - 가위바위보 손동작 인식 (MediaPipe 제스처 인식 연동)
   - 지정 사물(물병, 칫솔, 컵, 책 등 COCO 80종 사물)을 카메라에 비춰야만 알람 해제
2. **2차 수면 방지 로직 강화**:
   - 팝업 타임아웃(15초) 내 미확인 시 **더 강한 재알람(Re-Alarm)** 발동
   - 화면 클릭 대신 실제 방 안의 물리적 터치패드/버튼을 눌러야 팝업 해제
   - PIR 인체감지 모션 센서로 2차 수면 여부 감지
3. **사용자 경험(UX) 개선**:
   - 요일별/시간대별 다중 알람 스케줄러 기능
   - 기상 성공 기록 및 통계 로그 대시보드 차트 시각화

### 4-2. AI 요청 시 3대 원칙
1. **맥락 먼저 전달**: 항상 `docs/03-2차개발-생성형AI-핸드오버-가이드.md` 1장의 기본 시스템 프롬프트를 먼저 제공합니다.
2. **외과적 변경 요청**: 파일 전체를 다시 작성하게 하지 말고, 수정할 함수나 컴포넌트만 지정해서 수정을 요청합니다.
3. **역할 지정**: "너는 이 프로젝트의 `vision-agent`다" 또는 `backend-agent`, `frontend-agent`와 같이 역할을 명시합니다.

## 5단계. 클라우드 배포 (Supabase, Render, Vercel)

로컬 개발 및 실기기 연동이 완료되면 클라우드 환경으로 배포하여 외부에서도 접속 가능한 시스템으로 완성합니다.

```
┌────────────────────────┐      ┌────────────────────────┐
│  Render (FastAPI 백엔드)│ ◄──► │ Vercel (Next.js 웹 앱) │
└────────────────────────┘      └────────────────────────┘
            │
            ▼
┌────────────────────────┐
│ Supabase (PostgreSQL)  │
└────────────────────────┘
```

1. **데이터베이스 마이그레이션 (MySQL → Supabase)**:
   - Supabase 프로젝트 생성 후 SQL Editor에서 PostgreSQL 문법에 맞게 스키마 마이그레이션 실행
   - `.agents/skills/db-migration/SKILL.md` 참고
2. **백엔드 배포 (Render)**:
   - Render에서 Web Service 생성 후 GitHub 레포지터리 연결
   - Root Directory를 `backend`로 지정, Build Command: `pip install -r requirements.txt`, Start Command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
   - 환경변수 등록: `DATABASE_URL`, `DEVICE_API_KEY` 등
3. **프론트엔드 배포 (Vercel)**:
   - Vercel에 GitHub 레포지터리 연결, Root Directory를 `frontend`로 지정
   - 환경변수 `NEXT_PUBLIC_API_BASE_URL`을 Render 백엔드 도메인으로 설정

## 막혔을 때 (FAQ & 트러블슈팅)

| 상황 / 에러 메시지 | 해결 방법 |
|---|---|
| 라즈베리파이에서 백엔드 연결 실패 (`Connection refused` / 타임아웃) | 1) 백엔드 실행 시 `--host 0.0.0.0` 옵션을 주었는지 확인 (미지정 시 localhost만 접근 가능).<br>2) Windows 방화벽에서 8000번 포트 인바운드를 허용했는지 확인.<br>3) `pi/.env`의 `BACKEND_URL`에 `localhost` 대신 PC의 실제 IPv4(예: `192.168.x.x`)를 적었는지 확인. |
| `ModuleNotFoundError: No module named 'backend'` | `backend/main.py` 최상단에 `sys.path` 코드가 들어있으므로 `cd backend` 경로로 이동한 뒤 `uvicorn main:app`을 실행합니다. |
| `pip freeze` 후 인코딩 오류 (`charset=utf-16le`) | PowerShell에서 파일 저장 시 `pip freeze \| Out-File -Encoding utf8 requirements.txt` 명령을 사용합니다. |
| 웹캠 화면이 검은색이거나 열리지 않음 | Zoom, Teams, Discord, 브라우저 화상통화, Windows 카메라 앱 등이 웹캠을 점유하고 있는지 확인하고 작업 관리자에서 모두 종료합니다. |
| `401 Unauthorized` (디바이스 통신 실패) | `backend/.env`, `vision/.env`, `pi/.env` 3개 파일의 `DEVICE_API_KEY` 값이 정확히 일치하는지 확인합니다. |
