# 학생용 설치 및 사용 매뉴얼 (기상 유도 알람 시스템)

> 이 매뉴얼은 **기상 유도 알람 시스템** 팀에 맞게 예시를 채워 넣은 버전입니다. 이 킷의
> `.agents/`(rules/skills/workflows/hooks/agents), 핵심 보일러플레이트 코드, 그리고
> **`AGENTS.md`까지 이미 이 프로젝트에 맞게 준비되어 있습니다** — 1단계의 PRD 작성·
> AGENTS.md 완성 과정은 이미 끝나 있으니 내용을 확인만 하고 넘어가면 됩니다(왜 이렇게
> 채워졌는지는 `docs/기상유도알람시스템-AGENTS-초안-및-보충가이드.md` 참고).
> 아래 프롬프트의 액추에이터·미션 이름은 모두 우리 팀 실제 값으로 채워져 있으니 그대로
> 따라 하면 됩니다.
>
> 각 단계의 프롬프트/확인 방법은 이 문서를 따르고, 진행 체크만 빠르게 하고 싶다면
> `docs/학생-수작업-로드맵.md` 체크리스트를 함께 씁니다(체크리스트는 범용 버전이니
> 항목 이름만 우리 팀 것으로 바꿔서 사용합니다).

## 0단계. GitHub에서 받기 + 하네스 구축 (팀당 딱 한 번만)

### 0-1. 저장소 받기
팀장 또는 백엔드 담당 1명만 하면 됩니다. PowerShell에서:
```powershell
git clone -b wakeup [교사가 안내한 GitHub 저장소 주소] 기상-유도-알람-시스템
cd 기상-유도-알람-시스템
```
Git이 익숙하지 않다면, GitHub 저장소 페이지에서 **브랜치를 `wakeup`으로 전환한 뒤
Code → Download ZIP**으로 받아 압축을 풀고 그 폴더로 이동해도 됩니다.

> ⚠️ 반드시 **`wakeup` 브랜치**를 받아야 합니다. `main` 브랜치는 여러 팀이 함께 쓰는
> 범용 템플릿이라 이 팀 전용 `AGENTS.md`와 `alarm-scheduling-integration` 스킬이 들어
> 있지 않습니다.

**확인**: `AGENTS.md`, `.agents/`, `docs/`, `backend/`, `frontend/`, `vision/`, `pi/`가 들어있으면 성공입니다 — 공통 인터페이스(`backend/iot/base.py`, `backend/websocket_manager.py`, `frontend/components/dashboard/ConnectionBadge.tsx`)와 모델 가중치(`vision/yolov8n.pt`)는
교사가 미리 완성해서 저장소에 올려둔 것이라 별도 설치 과정이 필요 없습니다. `AGENTS.md`를
열어 팀 주제가 "기상 유도 알람 시스템"으로 이미 채워져 있는지도 확인합니다.

### 0-2. Antigravity로 열기
Antigravity IDE에서 방금 받은 폴더를 워크스페이스로 엽니다.

### 0-3. 하네스 구축 프롬프트 — 프로젝트 뼈대 완성
스타터 킷에 기본 구조가 준비되어 있습니다. Next.js 프론트엔드 스캐폴드와 백엔드 가상환경을 준비합니다.
> 💡 **참고**: Windows PowerShell에서 `pip freeze`를 할 때는 인코딩 충돌을 방지하기 위해 항상 UTF-8로 저장합니다:
> `pip freeze | Out-File -Encoding utf8 requirements.txt`

Antigravity 채팅창에 아래 프롬프트를 입력해 스캐폴드를 완성합니다:

```
이 프로젝트에는 이미 AGENTS.md, .agents/ 하네스, 그리고 기본 보일러플레이트(backend/iot/base.py, backend/websocket_manager.py, vision/yolov8n.pt 등)가 준비되어 있어. 
AGENTS.md의 기술 스택과 폴더 구조를 참고해서 아래를 완성해줘.

1. frontend/ — Next.js(TypeScript, Tailwind) 프로젝트 스캐폴드 (.env.example 충돌 없이 생성)
2. backend/ — Python venv를 활성화하고 requirements.txt(fastapi, uvicorn[standard], websockets, pymysql, python-dotenv, httpx 포함)의 패키지를 설치해줘
3. .gitignore — venv/, __pycache__/, *.pyc, .env, .env.local, node_modules/, .next/ 를 포함해줘
4. 각 폴더의 .env.example을 확인하고 누락된 항목이 없도록 정리해줘

AGENTS.md, .agents/, docs/ 폴더 및 사전 탑재된 유틸리티 파일은 이미 완성되어 있으니 절대 임의로 삭제하거나 덮어쓰지 마 (karpathy-principles.md의 "외과적 변경" 원칙).
```

**확인**: `frontend/`, `backend/`(안에 `venv/`, `requirements.txt`), `vision/`,
`pi/`, `.gitignore`, 그리고 4개의 `.env.example`이 생겼는지 확인합니다.

### Antigravity 인식 확인
Antigravity IDE에서 이 폴더를 워크스페이스로 엽니다. 상단 "…" 메뉴 → **Customizations** 패널에서
Rules/Skills/Workflows 목록에 방금 설치된 항목들이 보이는지 확인합니다. 안 보이면 워크스페이스를
닫았다가 다시 엽니다. Skills 목록에 `alarm-scheduling-integration`이 함께 보이면 이 팀 전용
스킬이 정상적으로 인식된 것입니다.

**⚠️ Rules는 3개만 "Always On"으로 설정하세요.** Customizations → Rules에서 아래
3개만 **Always On**으로 켭니다.
- `karpathy-principles` (모든 작업의 기본 전제)
- `security-rules`
- `coding-standards`

나머지 규칙(`api-rules`, `db-rules`, `hardware-rules`, `vision-rules`, `git-rules`,
`deploy-rules`, `ui-ux-rules`)은 Always On으로 켜지 않아도 됩니다 — 각 `agent.md`의
"항상 참고" 항목에 이미 연결돼 있어서, 해당 역할(예: db-agent)을 부를 때 AI가
자동으로 읽습니다. 10개를 전부 Always On으로 켜면 채팅마다 안 쓰는 규칙까지
매번 8,000~12,000 토큰을 소모하므로, 딱 이 3개만 켜는 것이 무료 티어 유지의 핵심입니다.

## 2단계 (1주차). Mock 백엔드 + DB + 대시보드 베이스라인

> 🖥️ **동시 실행 멀티 터미널 안내**:
> IoT 시스템은 여러 프로세스가 실시간으로 통신합니다. **터미널을 3개 열어 각각 실행 상태를 유지**해야 합니다:
> - **터미널 1**: 백엔드 API & WebSocket (`uvicorn main:app --reload --port 8000`)
> - **터미널 2**: Next.js 대시보드 (`npm run dev`)
> - **터미널 3**: 비전 인식 클라이언트 (`python vision/main.py` — 3단계에서 실행)

```
┌─────────────────────────┐   WebSocket / REST    ┌─────────────────────────┐
│  터미널 1: 백엔드 (8000)  │ ◄──────────────────► │ 터미널 2: 프론트엔드(3000) │
└─────────────────────────┘                       └─────────────────────────┘
             ▲
             │ POST /api/v1/vision/events
┌─────────────────────────┐
│  터미널 3: 비전 클라이언트 │
└─────────────────────────┘
```

### 2-1. 백엔드 환경 준비 (직접 실행)
```powershell
# [터미널 1]
cd backend
.\venv\Scripts\Activate.ps1
```
XAMPP를 켜서 MariaDB를 실행하고, phpMyAdmin에서 DB(`wakeup_alarm` 등 우리 팀 이름)를 만듭니다.
`backend/.env`에 DB 접속 정보를 채웁니다.

### 2-2. DB + Mock 디바이스 + API

이 팀은 desired-state 폴링 대상 디바이스가 **알람 출력 장치 하나**뿐입니다 — 카메라는
`devices` 테이블/DeviceProvider 대상이 아니라 3단계의 vision 클라이언트가 별도로
처리합니다. 대신 알람 시각과 기상 미션 진행 상태를 담을 테이블이 추가로 필요하므로,
`alarm-scheduling-integration` 스킬을 함께 참고합니다.

```
너는 이 프로젝트의 db-agent다. .agents/skills/db-integration/SKILL.md와
.agents/skills/alarm-scheduling-integration/SKILL.md를 따른다.

db-rules.md의 최소 스키마로 backend/db.py와 backend/db/init.sql을 만들어줘.
init.sql에는 AGENTS.md 팀 정보의 액추에이터(알람 출력 장치)를 devices 테이블 시드
데이터로 포함하고, alarm-scheduling-integration 스킬의 alarms/wakeup_sessions
테이블과 vision_events 컬럼 확장(mission_type, label)도 함께 만들어줘.
```

### 2-2-1. DB 초기화 스크립트 실행 (직접 실행)
AI가 만든 `init.sql`은 파일로만 존재할 뿐, 아직 MySQL에 반영되지 않았습니다.
XAMPP MySQL이 켜진 상태에서 PowerShell로 직접 실행합니다.
```powershell
cd backend
Get-Content db\init.sql | mysql -u root
```
(mysql 명령이 PATH에 없다면, phpMyAdmin 웹 화면의 **SQL 탭**에 `init.sql` 내용을 그대로 붙여넣어 실행해도 됩니다.)

**확인**: phpMyAdmin에서 `devices` 테이블에 알람 출력 장치 행이 들어있고, `alarms`,
`wakeup_sessions` 테이블이 함께 생성되어 있는지 확인합니다.

```
너는 이 프로젝트의 hardware-agent다. .agents/skills/hardware-integration/SKILL.md를 따른다.

backend/iot/base.py의 DeviceProvider를 상속받아 우리 팀 액추에이터(알람 출력 장치)에
대한 MockDeviceProvider를 만들어줘. devices 테이블의 id 값과 일치시켜줘.
```

```
너는 이 프로젝트의 backend-agent다. .agents/skills/iot-endpoint-generator/SKILL.md와
.agents/skills/alarm-scheduling-integration/SKILL.md를 따른다.

알람 출력 장치에 대한 조회/제어 엔드포인트와 backend/main.py 라우팅을 완성하고,
alarm-scheduling-integration 스킬대로 알람 스케줄링 백그라운드 태스크와
GET /api/v1/vision/current-mission 엔드포인트도 함께 만들어줘.
```

### 2-2-2. 백엔드 서버 실행 (터미널 1)
```powershell
# [터미널 1]
cd backend
uvicorn main:app --reload --port 8000
```
> 💡 `backend/main.py` 최상단에 `sys.path` 자동 추가 코드가 탑재되어 있으므로 `ModuleNotFoundError: No module named 'backend'` 에러 없이 정상 구동됩니다.

**확인**: 브라우저에서 `http://localhost:8000/docs`(Swagger) 및 `http://localhost:8000/health` 접속 확인.

### 2-3. 대시보드 (터미널 2)
먼저 새 터미널을 열고 필요한 패키지를 직접 설치합니다.
```powershell
# [터미널 2]
cd frontend
npm install
npm install lucide-react
```
```
너는 이 프로젝트의 frontend-agent다. .agents/rules/ui-ux-rules.md와
.agents/skills/dashboard-ui-design/SKILL.md를 따른다.

사전 제공된 components/dashboard/statusColor.ts와 ConnectionBadge.tsx를 활용해서,
알람 출력 장치 상태를 보여주는 실시간 대시보드를 만들어줘. 알람이 울리는 중일 때는
AlertCard 패턴(자동으로 꺼지지 않고 대시보드에서 수동으로 해제하는 방식)으로 표시하고,
시간 렌더링에는 suppressHydrationWarning을 적용해줘.
```

### 2-3-1. 프론트엔드 서버 실행 (터미널 2)
```powershell

npm run dev
```
**확인**: 브라우저에서 `http://localhost:3000` 접속 후 실시간 연결 상태 배지("● 실시간 연결됨")와 디바이스 카드 동작을 확인합니다.
(백엔드가 꺼져있을 때는 배지가 "● 연결 대기 중"으로 부드럽게 표시됩니다.)

## 3단계 (2주차). 영상인식(가위바위보·사물인식) → 기상 미션 판정

이 프로젝트는 기본 킷 예시("사람 감지 → 즉시 액추에이터 제어")와 다르게 동작합니다.
**미션 단계에 따라 인식 대상이 바뀌고**, 인식 결과가 액추에이터를 직접 켜고 끄는 게
아니라 **미션 통과/실패 판정**으로 이어집니다. 순서는 다음과 같습니다: 웹캠 클라이언트를
준비하고(3-1), 미션 판정·알람 종료 로직을 백엔드에 연결하고(3-2), 마지막으로 미션을
직접 테스트할 수 있는 화면을 완성합니다(3-3).

### 3-1. 웹캠 감지 클라이언트 준비
> ⚠️ **웹캠 충돌 방지 사전 체크 (필수)**:
> Windows는 하나의 웹캠을 한 번에 한 프로그램만 점유할 수 있습니다.
> 시작 전에 **Zoom, Teams, Discord, 브라우저 화상채팅, Windows 카메라 앱 등을 모두 종료**하세요.

> 🚀 **YOLOv8 모델 사전 탑재 안내**:
> 실습실 30~40명이 동시에 모델을 다운로드하여 학내망이 차단되는 문제를 막기 위해, `vision/yolov8n.pt`(6.2MB) 가중치 파일이 이미 저장소에 포함되어 있습니다. 별도 다운로드 없이 즉시 실행할 수 있습니다.

새 터미널(터미널 3)에서 의존성을 설치합니다:
```powershell
# [터미널 3]
cd vision
```

## 막혔을 때 (FAQ & 트러블슈팅)

| 상황 / 에러 메시지 | 해결 방법 |
|---|---|
| `ModuleNotFoundError: No module named 'backend'` | `backend/main.py` 최상단에 `sys.path` 주입 코드가 포함되어 있는지 확인하거나, `cd backend` 경로에서 `uvicorn main:app`을 실행합니다. |
| `pip freeze` 후 `unsupported mime type charset=utf-16le` 에러 | PowerShell의 기본 리다이렉션 대신 `pip freeze \| Out-File -Encoding utf8 requirements.txt` 명령을 사용합니다. |
| `RuntimeError: The starlette.testclient module requires the httpx package` | 백엔드 가상환경에서 `pip install httpx`를 실행합니다 (`backend/requirements.txt`에 포함됨). |
| Next.js 대시보드 `Hydration failed` 경고 | 시간 렌더링 태그에 `suppressHydrationWarning` 속성을 추가하거나 `components/dashboard/ConnectionBadge.tsx`를 사용합니다. |
| `Control request failed: Failed to fetch` | 백엔드 서버(터미널 1: `http://localhost:8000`)가 켜져 있는지 확인합니다. |
| 웹캠 화면이 검은색으로 나오거나 멈춤 | Zoom, Teams, 브라우저 등 웹캠을 점유 중인 다른 프로그램을 모두 작업 관리자에서 종료합니다. |
| `pip install ultralytics` 경로 길이 오류 (`[WinError 206]`) | 관리자 권한 PowerShell에서 `New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" -Name "LongPathsEnabled" -Value 1 -PropertyType DWORD -Force` 실행 후 재부팅합니다. |
| `Activate.ps1` 실행 불가 (`PSSecurityException`) | PowerShell에서 `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` 실행 후 다시 활성화합니다. |
| `mysql: command not found` | `C:\xampp\mysql\bin\mysql.exe -u root`로 직접 지정하거나 phpMyAdmin 웹 UI SQL 탭에 붙여넣어 실행합니다. |
| `mediapipe` 설치 실패 / `ModuleNotFoundError: No module named 'mediapipe'` | `vision/requirements.txt`에 포함되어 있는지 확인한 뒤, vision venv를 활성화한 상태에서 `pip install mediapipe`를 다시 실행합니다. |
| 가위바위보 손동작이 자주 오인식됨 | 손 전체가 웹캠 프레임 중앙에 크게 들어오도록, 조명이 밝은 곳에서 보여주도록 안내합니다(mediapipe Hands는 손 전체가 보여야 정확도가 올라갑니다). |
| 현재 미션 폴링이 항상 `active: false`로만 나옴 | `wakeup_sessions`에 진행 중인(`status`가 `mission_in_progress` 등인) 행이 있는지 DB에서 직접 확인합니다 — 알람이 아직 울리지 않았다면 정상 동작입니다. |
