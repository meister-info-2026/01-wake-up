# PRD 공통 양식
## 대한민국 전자계열 마이스터고등학교 정보통신과 2학년 팀 프로젝트

> **문서 목적**
>
> 각 팀이 미팅을 통해 작성한 **「프로젝트 개발 계획서」**를 입력 자료로 사용하여, 생성형 AI가 실제 개발에 사용할 수 있는 **Product Requirements Document(PRD)**를 일관된 형식으로 생성하기 위한 공통 양식이다.
>
> **작성 원칙**
> 1. 프로젝트 개발 계획서의 내용을 최우선으로 반영한다.
> 2. 계획서에 없는 기능을 AI가 임의로 추가하지 않는다.
> 3. 계획서에서 결정되지 않은 내용은 `[미정]`으로 표시한다.
> 4. 개발을 쉽게 하기 위한 AI의 제안은 `[권장]`으로 표시한다.
> 5. 계획서의 표현과 의도를 가능한 한 유지한다.
> 6. 학생들이 실제 구현할 수 있는 수준으로 구체화하되, 과도한 기술이나 복잡한 구조를 임의로 추가하지 않는다.
> 7. 공통 개발환경과 기술 스택은 아래의 **고정 개발환경**을 따른다.
> 8. 프로젝트별로 필요하지 않은 항목은 `해당 없음`으로 표시하되 임의의 기능을 추가하지 않는다.
> 9. 모든 요구사항은 구현 → 테스트 → 검증이 가능하도록 작성한다.
> 10. PRD 작성 후 마지막에 **「프로젝트 개발 계획서 ↔ PRD 일치 여부 검증」**을 반드시 수행한다.

# 1. 프로젝트 개요

## 1.1 프로젝트 기본 정보

| 항목 | 내용 |
|---|---|
| 프로젝트명 | 기상 유도 알람 시스템 |
| 프로젝트 주제 | 알람 이후 기상 미션과 2차 수면 방지 기능을 포함한 스마트 기상 시스템 |
| 팀명 | `[미정]` |
| 팀원 | `[미정]` |
| 프로젝트 유형 | 스마트 시스템 |
| 개발 기간 | `[미정]` |

## 1.2 한 줄 목표

> 사용자가 알람을 끈 뒤 다시 잠드는 문제를 줄이기 위해 기상 미션을 수행하게 하고, 미션 후 일정 시간이 지나면 기상 확인 팝업으로 2차 수면 여부를 확인하는 시스템을 구현한다.

## 1.3 프로젝트 설명

사용자가 설정한 시간에 알람을 울리고, 알람을 끈 후 기상 미션을 수행하도록 하는 스마트 기상 시스템이다. 기상 미션은 손동작 기반 가위바위보, 사물인식, 패턴 순서 기억하기로 구성한다. 사용자가 미션을 완료하면 알람은 종료되며, 약 1~2분(`[미정]`) 뒤 패드 화면에 기상 확인 팝업을 표시한다. 팝업을 확인하지 않으면 사용자가 다시 잠들었을 가능성이 있는 것으로 판단하여 알람을 다시 울린다.

## 1.4 프로젝트 핵심 기능

프로젝트 개발 계획서에 명시된 핵심 기능만 작성한다.

1. 알람 설정 및 알람 동작
2. 기상 미션 수행(가위바위보 손동작, 사물인식, 패턴 순서 기억하기)
3. 미션 완료 후 기상 확인 팝업 및 2차 알람

# 2. 문제와 목표

## 2.1 해결하려는 문제

사용자가 알람을 끈 뒤 다시 잠드는 문제를 줄일 필요가 있다. 단순히 알람을 끄는 것에서 끝나지 않고, 사용자가 직접 미션을 수행하도록 하며 미션 이후에도 기상 상태를 확인하는 과정이 필요하다.

## 2.2 프로젝트 목표

### 기능 목표
- 사용자가 UI에서 알람 시간을 설정할 수 있도록 한다.
- 알람 해제를 위해 기상 미션을 수행하도록 한다.
- 미션 완료 후 기상 확인 팝업을 표시하고, 확인하지 않으면 알람을 다시 울리도록 한다.

### 기술 목표
- 가위바위보 손동작을 인식할 수 있도록 AI 학습 및 인식 기능을 구현한다.
- 화면에 제시된 사물을 카메라로 인식할 수 있도록 AI 학습 및 인식 기능을 구현한다.
- 난수로 생성된 패턴을 보여주고 사용자의 입력 순서를 검증하는 기능을 구현한다.

## 2.3 성공 기준

| 기준 | 목표값 | 검증 방법 |
|---|---|---|
| 알람 설정 | 설정한 시간에 알람 동작 | 여러 시간으로 설정 후 실제 동작 확인 |
| 기상 미션 | 선택한 미션을 정상 수행하면 통과 | 정상 입력/오입력으로 각각 테스트 |
| 2차 수면 방지 | 팝업 미확인 시 알람 재동작 | 미션 완료 후 팝업 미확인 상태를 재현하여 확인 |
| 패턴 기억 | 생성된 순서와 사용자 입력 순서가 일치하면 통과 | 정답/오답 패턴으로 테스트 |
| AI 인식 | `[미정]` | 가위바위보 및 사물인식 테스트 데이터로 검증 |

## 4.1 기능별 상세 요구사항

### F-01 알람 설정 및 알람 동작
- 목적: 사용자가 원하는 기상 시간을 설정하도록 한다.
- 입력: 알람 시간, `[추가 설정 항목 미정]`
- 처리: 설정된 시간과 현재 시간을 비교하여 알람을 동작시킨다.
- 출력: 알람 화면 및 알람음(`[알람 장치 미정]`)
- 정상 동작: 설정 시간에 알람이 울린다.
- 예외 상황: `[미정]`
- 완료 조건: UI에서 설정한 시간에 알람이 정상 동작한다.

### F-02 가위바위보 손동작 미션
- 목적: 사용자가 손동작을 수행하도록 하여 기상 상태를 확인한다.
- 입력: 카메라 영상, 가위/바위/보 손동작
- 처리: AI가 손동작을 인식하고 제시된 정답과 비교한다.
- 출력: 성공/실패 결과
- 정상 동작: 올바른 손동작을 인식하면 미션을 통과한다.
- 예외 상황: 손동작을 제대로 인식하지 못하면 `[재시도 방식 미정]`
- 완료 조건: AI가 정답 손동작을 정상적으로 판별한다.

### F-03 사물인식 미션
- 목적: 사용자가 실제 사물을 가져오도록 하여 기상 상태를 확인한다.
- 입력: 카메라 영상, 지정 사물
- 처리: 화면에 “ㅇㅇ을 보여주세요”를 표시하고 AI가 카메라 영상의 사물을 인식한다.
- 출력: 성공/실패 결과
- 정상 동작: 요청한 사물을 화면에 보여주면 통과한다.
- 예외 상황: 사물이 인식되지 않거나 다른 사물을 보여주면 `[재시도 방식 미정]`
- 완료 조건: 요청한 사물을 AI가 정상적으로 판별한다.

### F-04 패턴 순서 기억 미션
- 목적: 사용자가 화면에 제시된 패턴 순서를 기억하고 입력하도록 한다.
- 입력: 난수로 생성된 패턴, 사용자 입력, 타이머
- 처리: 패턴을 생성하고 타이머를 시작한다. 사용자의 입력 순서를 생성된 배열과 비교한다. 틀리면 배열을 초기화하고 다시 시작한다.
- 출력: 패턴, 남은 시간, 성공/실패 결과
- 정상 동작: 제한 시간 내 올바른 순서로 입력하면 통과한다.
- 예외 상황: 제한 시간 초과 또는 잘못된 순서 입력 시 배열을 초기화하고 재시작한다.
- 완료 조건: 정답 패턴 입력 시 미션이 통과되고 오답 시 재시작된다.

### F-05 기상 확인 및 2차 알람
- 목적: 사용자가 미션 완료 후 다시 잠드는 문제를 줄인다.
- 입력: 미션 완료 상태, 기상 확인 팝업 확인 여부
- 처리: 미션 완료 후 약 1~2분(`[미정]`) 뒤 기상 확인 팝업을 표시한다. 사용자가 팝업을 확인하지 않으면 알람을 다시 울린다.
- 출력: 기상 확인 팝업 또는 재알람
- 정상 동작: 사용자가 팝업을 확인하면 기상 과정이 종료된다.
- 예외 상황: 팝업 미확인 시 알람을 다시 울린다.
- 완료 조건: 팝업 확인 여부에 따라 종료 또는 2차 알람이 정상적으로 동작한다.

# 30. 프로젝트 개발 계획서 ↔ PRD 일치 여부 검증

> **필수 작성 항목**
>
> 제공된 1번 파일은 파일명과 달리 실제 「팀별 프로젝트 개발 계획서」 원문이 아니라 PRD 공통 양식에 맞춰 이미 작성된 프로젝트 PRD 형태의 문서이다. 따라서 실제 팀원 역할, 일정 등 원본 계획서에만 있을 수 있는 정보는 확인할 수 없으며, 확인되지 않은 내용은 `[미정]`으로 유지한다. 이 점을 포함하여 두 첨부 파일의 내용과 PRD 반영 여부를 검증한다.

| 검증 항목 | 개발 계획서 내용 | PRD 반영 내용 | 일치 여부 |
|---|---|---|---|
| 프로젝트 주제 | 알람 이후 기상 미션과 2차 수면 방지 기능을 포함한 스마트 기상 시스템 | 기상 유도 알람 시스템 및 동일한 프로젝트 주제로 반영 | 일치 |
| 프로젝트 목표 | 알람을 끈 뒤 다시 잠드는 문제를 줄이고 기상 미션 및 기상 확인 절차를 적용 | 기상 미션 + 기상 확인 팝업 + 미확인 시 2차 알람으로 반영 | 일치 |
| 핵심 기능 | 알람 설정/동작, 가위바위보, 사물인식, 패턴 순서 기억, 기상 확인 및 2차 알람 | F-01~F-05로 반영 | 일치 |
| 센서 | 카메라 영상 입력, 패드 화면/터치 입력 | S-01 카메라, S-02 패드 화면/터치 입력으로 반영 | 일치 |
| 액추에이터 | 알람 출력 | A-01 알람 출력 장치로 반영하되 구체 장치/제어 방식은 `[미정]` | 부분일치 |
| 시스템 구성 | Frontend → Backend → MySQL/Raspberry Pi 5 및 센서/액추에이터 구조 | Next.js → FastAPI → MySQL/Raspberry Pi 5 구조로 반영 | 일치 |
| 팀원 역할 | 원본 계획서의 실제 팀원 역할 정보 확인 불가 | 담당자 및 역할을 `[미정]`으로 유지 | 일치 |

## 30.1 계획서에서 누락된 내용

- 제공된 1번 파일에는 실제 팀별 프로젝트 개발 계획서 원문이 아니라 이미 PRD 형태로 정리된 내용이 포함되어 있다.
- 따라서 실제 계획서에서 별도로 확인해야 할 **팀명, 실제 팀원명, 팀원별 역할, 개발 기간, 세부 일정, 실제 기구물 제작 목록, 실제 부품명** 등은 확인할 수 없다.
- 위와 같이 확인할 수 없는 항목은 임의로 채우지 않고 `[미정]`으로 유지했다.
- 핵심 프로젝트 기능 자체는 제공된 프로젝트 문서에 포함되어 있어 PRD에 반영했다.
