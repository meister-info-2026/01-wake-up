# karpathy-principles

> AI 에이전트가 코드를 작성하기 전에 항상 지키는 4가지 원칙. Andrej Karpathy의 LLM 코딩
> 실수 패턴 관찰(가정하고 그냥 진행함, 과하게 부풀림, 무관한 부분을 건드림, 모호한 목표로
> 대충 마무리함)에서 가져왔다. 이 rule은 다른 모든 rules/skills와 함께 항상 적용된다.

## 1. 생각 먼저 (Think Before Coding)
- 요청이 애매하면 추측해서 진행하지 말고, 가능한 해석을 제시하거나 질문한다
- 더 간단한 방법이 있으면 먼저 제안한다
- 확신이 없는 부분은 "이 부분이 불확실하다"고 명시적으로 말한다

## 2. 단순함 우선 (Simplicity First)
- 요청받은 것 이상으로 기능을 추가하지 않는다
- 나중에 필요할 것 같다는 이유로 미리 확장 가능하게 만들지 않는다 (YAGNI)
- 200줄로 짤 수 있는 걸 50줄로 될 것 같으면 다시 줄인다

## 3. 외과적 변경 (Surgical Changes)
- 요청과 무관한 코드/주석/포맷은 손대지 않는다 — 마음에 안 들어도 그대로 둔다
- 자신의 변경으로 안 쓰게 된 import/변수만 정리한다. 원래 있던 죽은 코드는 지우지 않고
  발견 사실만 언급한다
- 바뀐 모든 줄은 요청과 직접 연결되어야 한다

## 4. 목표 기반 실행 (Goal-Driven Execution)
- "~해줘" 대신 "성공 기준"으로 바꿔서 요청한다 (예: "검증 추가해줘" → "잘못된 입력에 대한
  테스트를 먼저 쓰고, 통과하게 만들어줘")
- 여러 단계가 필요한 작업은 시작 전에 간단한 계획을 제시한다: 1) 단계 → 확인 방법,
  2) 단계 → 확인 방법
- "됐다"고 말하기 전에 실제로 실행해서 확인한다 — 요약만 믿지 않는다

## 다른 rules와의 연결
- 3번(외과적 변경)은 git-rules.md의 PR 체크리스트("관련 없는 파일 변경이 섞이지
  않았는가")와 같은 원칙이다
- 4번(목표 기반 실행)은 workflows/feature-development.md의 "성공 기준 먼저 정의 →
  검증" 절차로 구체화되어 있다
