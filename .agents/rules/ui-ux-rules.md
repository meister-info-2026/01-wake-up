# UI/UX 규칙 (taste-skill · ui-ux-pro-max 참고)

> 학생 팀 프론트엔드는 대부분 "동작은 하는데 밋밋한" 상태로 끝나는 경우가 많다. 이 규칙은
> frontend-agent가 별도 요청 없이도 매번 최소한의 완성도를 보장하도록 만든 것이다.
> taste-skill(anti-slop 원칙)과 ui-ux-pro-max(체계적 디자인 시스템·배포 전 체크리스트)의
> 핵심만 이 프로젝트(IoT 대시보드) 규모에 맞게 정리했다 — 두 원본의 CLI 설치나 외부 검색
> 엔진(Python 스크립트, 192개 산업별 추천)은 설정 부담이 커서 의도적으로 가져오지 않았다.

## 이 프로젝트의 디자인 시스템 (고정)
- 스타일: 대시보드형 — Linear/Notion 톤의 절제된 미니멀
- 위계: 카드마다 "디바이스 이름(작게) → 값/상태(크게) → 보조 정보(작게)" 순서로 크기
  차등을 준다. 경보성 디바이스(예: 침입감지)는 다른 카드보다 시각적으로 더 크게/눈에
  띄게 배치한다
- 색상 의미 (임의로 바꾸지 않는다)

  | 색 | 의미 |
  |---|---|
  | 초록 | 정상 / ON / 연결됨 |
  | 빨강 | 경고 / 감지됨 / 오류 |
  | 회색 | OFF / 비활성 / 연결 끊김 |
  | 파랑 | 중립 수치 정보(온도·조도 등) |

- 아이콘: 이모지를 아이콘 대용으로 쓰지 않는다 — `lucide-react` 등 실제 SVG 아이콘
  라이브러리를 사용한다
- 폰트: 시스템 기본 산세리프 사용. 한글 폰트가 필요하면 `next/font`로 로컬 서빙한다
  (외부 폰트 API 호출을 늘리지 않는다)

## Anti-Slop 체크 (taste-skill 원칙)
- "AI가 만든 티가 나는" 기본값을 피한다: 보라/핑크 그라디언트 배경, 전부 같은 크기
  카드만 나열한 밋밋한 그리드, 그림자 없는 flat 카드
- 레이아웃에 최소한의 의도적 변주를 준다 — 모든 카드를 똑같은 크기로 나열하지 않는다
- 상태가 바뀔 때(ON/OFF, 값 갱신) 200ms 내외의 짧은 트랜지션을 준다 — 과한 애니메이션은
  피한다
- 여백을 충분히 준다 — 요소를 다닥다닥 붙이지 않는다

## 배포 전 체크리스트 (ui-ux-pro-max 참고, 이 프로젝트 규모로 축소)
- [ ] 이모지를 아이콘 대용으로 쓰지 않았는가
- [ ] 클릭 가능한 요소에 `cursor-pointer`가 적용되어 있는가
- [ ] 텍스트 대비가 충분한가 (옅은 회색 글씨 on 밝은 배경 같은 저대비 조합 금지)
- [ ] 키보드로 포커스 이동 시 포커스 표시가 보이는가
- [ ] 디바이스 이름이 길어져도 카드 레이아웃이 깨지지 않는가 (줄바꿈/말줄임 처리)
- [ ] 모바일 폭(375px)에서도 레이아웃이 깨지지 않는가
- [ ] WebSocket 연결이 끊긴 상태가 화면에 명확히 표시되는가 (끊긴 채로 마지막 값만
      계속 보여주면 사용자가 실시간이라고 착각한다)

## 다른 rules와의 연결
- karpathy-principles.md의 "단순함 우선"과 이 규칙의 "여백/절제"는 같은 방향이다 —
  화려하게 꾸미라는 뜻이 아니라, 기본값을 그대로 쓰지 말고 의도를 갖고 다듬으라는 뜻이다
- 구체적인 컴포넌트 패턴은 `dashboard-ui-design` 스킬을 참고한다
