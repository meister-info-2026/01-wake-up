# API 규칙

## 엔드포인트 네이밍
- 리소스 중심, 복수형: `GET /api/devices`, `POST /api/devices/{id}/control`
- 영상인식 이벤트 수신: `POST /api/v1/vision/events`
- 디바이스 상태 폴링(하드웨어용): `GET /api/v1/devices/{id}/desired-state`,
  `POST /api/v1/devices/{id}/state`

## 응답 형식
- 성공: `{ "data": ... }`
- 실패: `{ "error": { "code": "...", "message": "..." } }`
- 상태 코드: 인증 실패 401, 권한 없음 403, 유효성 실패 422, 리소스 없음 404

## 인증 분리 (반드시 지킬 것)

| 엔드포인트 종류 | 인증 방식 |
|---|---|
| 사용자향 (대시보드에서 호출) | Supabase Auth JWT 검증 |
| 디바이스향 (라즈베리파이, 영상인식 클라이언트) | 디바이스 API 키 (`X-Device-Api-Key` 헤더, 해시 대조) |

두 인증 경로를 절대 섞지 않는다. 디바이스향 엔드포인트에 사용자 JWT를 요구하거나,
사용자향 엔드포인트에 디바이스 키만으로 접근 가능하게 만들지 않는다. (이전 유사 프로젝트에서
이 구분이 빠져 실제 문제가 된 적이 있으므로 처음부터 분리해서 설계한다.)
